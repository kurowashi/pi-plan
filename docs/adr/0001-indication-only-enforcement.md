# ADR 0001: plan mode 中の書き込みはプロンプトで指示し、技術的なブロックを置かない

- 状態: 採用
- 日付: 2026-10-04
- 対象: plan mode 中の `write` / `edit` / Bash の扱い

## 背景

- Claude Code は plan 権限モードと権限プロンプトで書き込みを制御する。plan mode 中もプランファイルへの書き込みは許可され、それ以外はユーザーの確認を挟む。
- Pi に権限モードと権限プロンプトの層はない。Pi 拡張が書き込みを止めるには `tool_call` フックで deny する必要がある。
- 判断基準は Claude Code との互換性とする([DESIGN.md](../DESIGN.md))。

## 決定

1. plan mode 中の読み取り専用はプロンプトで指示する。
2. `tool_call` フックによるブロック、確認ダイアログ、Bash 許可リストは置かない。
3. 指示に反した書き込みを止める仕組みを持たないことを DESIGN.md と README に記録する。

## 理由

- Claude Code の plan 権限モードは書き込みを止めず、ユーザーに確認する。承認すれば書き込める。
- `tool_call` フックの deny には承認経路がなく、Claude Code より厳しい挙動になる。互換性を下げる。
- Bash の許可リストは判定が本質的に不完全で、fail-open と fail-closed のどちらでも誤りを生む。維持コストに見合わない。
- プロンプト指示はセッションに記録され、テストで文面を拘束できる。

## 帰結

- モデルが指示に違反して書き込む可能性が残る。読み取り専用は保証されない。
- Claude Code より弱い保証になる。利用者はこの差を認識する必要がある。

## 代替案

| 代替 | 却下理由 |
|---|---|
| `tool_call` フックで許可リスト外を deny する | Claude Code の承認経路を再現できず、互換性が下がる |
| 書き込みの前にユーザー確認ダイアログを出す | Claude Code の権限プロンプト層の再実装になり、維持コストが大きい |
